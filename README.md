## Что на странице

1. **Первый экран** — кто я и живой пример: заявка разбирается на поля, у каждого поля есть цитата, недостающее уходит вопросом человеку.
2. **Проекты** — сначала решения на данных и LLM: PipePass (цифровой паспорт бурильной трубы, на данных заказчика), AgentYard (оркестратор агентов), ассистенты по базе знаний, Freight Intake. Потом внутренние инструменты.
3. **Под вашу вакансию** — каждое требование из описания и чем я его подтверждаю. Пробелы подписаны как пробелы.
4. **Знаю, как устроены процессы** — что я делал в системах, где похожий процесс у сети кухонь и магазинов, какой пилот с ИИ я бы проверил.
5. **Коммерческий опыт, как веду внедрение, стек с уровнями, опыт и образование, контакты.**
6. **Спросите резюме** — маленький поиск по базе знаний, где база — сама страница.

## Как устроено

```text
src/content/site.ts ──► App.tsx ──► entry-server ──► dist/index.html (готовый HTML)
        │                  │
        │                  └── острова: IntakeDemo, VideoShowcase, FitMatrix, AskWidget
        │                         оживают в браузере, когда до них доскроллили
        └──► corpus.ts ──► фрагменты для «Спросите резюме» и для rag/
```

- **Статичный HTML + «острова».** Страница собирается в готовый HTML при сборке: первый экран виден сразу, превью ссылки в Telegram и поисковики видят текст. JavaScript грузится кусками только для интерактивных блоков. Стартовый скрипт — около 2 КБ.
- **Сборка — свой скрипт на esbuild** (`scripts/build.mjs`, около 140 строк): клиентский бандл с чанками, серверный бандл, пререндер, копирование статики. Страница одна, фреймворк для неё не нужен.
- **«Спросите резюме» и контракт API.** Виджет шлёт `POST /api/ask` и читает ответ потоком SSE. На GitHub Pages сервера нет, поэтому запрос обрабатывает функция в браузере с той же сигнатурой: принимает `Request`, отдаёт `Response`. Если при сборке задать `ASK_API_URL`, тот же виджет пойдёт на настоящий сервер из `rag/` — код виджета не меняется.
- **Почему здесь нет MSW.** MSW подменяет много эндпоинтов, когда фронтенду нужен целый бэкенд. Здесь эндпоинт один, и функция-транспорт решает ту же задачу без сервис-воркера — а значит, без сюрпризов с подпапкой на GitHub Pages и в приватном режиме браузера. MSW в полную силу работает в PipePass и Freight Intake.
- **Честные подписи.** Ответы виджета по умолчанию — поиск по фрагментам без генерации, и это написано в интерфейсе. Если запустить `rag/record.py`, появятся ответы модели — с подписью модели и даты.
- **Движение только по делу:** сканирование заявки на первом экране, «пакет данных» в схемах цепочек, разворот витрины при прокрутке, волна при смене темы. Всё отключается при «уменьшить движение» в системе.

## Запуск

Нужен Node.js 22+.

```bash
npm install
npm run dev        # http://localhost:5173, пересборка при сохранении
npm run build      # сборка в dist/
npm run preview    # посмотреть собранное: http://localhost:4173
```

| Команда | Что делает |
| --- | --- |
| `npm test` | Модульные тесты: разбор SSE по одному символу, поиск, обработчик `/api/ask` |
| `npm run typecheck` | Проверка типов TypeScript |
| `npm run e2e` | Сквозная проверка собранного сайта в Chromium на телефоне и компьютере |
| `npm run images` | Нарезка картинок под адаптив — см. [docs/IMAGES.md](docs/IMAGES.md) |
| `npm run corpus` | Выгрузка фрагментов страницы в `rag/corpus.json` |
| `node scripts/og.mjs` | Картинка превью ссылки 1200×630 |
| `bash scripts/video.sh` | Пережать видео проекта для сайта (нужен ffmpeg) |

## Публикация на GitHub Pages

1. Создайте репозиторий `ai-portfolio` и отправьте в него код (ветка `main`).
2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Каждый push в `main` запускает `.github/workflows/deploy.yml`: проверка типов → тесты → сборка → сквозная проверка → публикация. Красная проверка публикацию останавливает.

Адрес сайта workflow определяет сам: для репозитория `<имя>.github.io` — корень домена, для остальных — подпапка. Все пути в HTML относительные, поэтому сайт работает в любом из вариантов.

Чтобы страницу не индексировали поисковики, соберите с `NOINDEX=1`.

## Генеративный режим «Спросите резюме» (rag/)

Postgres с pgvector, модели локально через Ollama.

```bash
npm run corpus                        # фрагменты страницы → rag/corpus.json
docker compose up -d                  # Postgres + pgvector на порту 5433
pip install -r rag/requirements.txt
ollama pull bge-m3 && ollama pull qwen2.5:7b
python -m rag.build                   # векторы фрагментов → таблица fragments
python -m rag.record                  # ответы модели на готовые вопросы → public/ask-recorded.json
uvicorn rag.api:app --port 8787       # живой сервер с тем же контрактом /api/ask
```

Поиск гибридный (`rag/sql/search.sql`): полнотекстовый по-русски плюс векторная близость, списки сливаются по рангам. Модель отвечает только по найденным фрагментам и ссылается на их id; ссылку на то, чего не было в найденном, код отбрасывает.

> Скрипты `rag/` проверены на синтаксис, но в среде, где собирался сайт, не было Postgres и Ollama — прогон на живых сервисах не делался.

## Структура

```text
src/
  content/      тексты страницы и фрагменты для поиска
  components/   разделы, картинки, схема цепочки, иконки
  islands/      интерактивные блоки и их загрузка
  lib/          поиск по фрагментам, разбор SSE, контракт /api/ask
  styles/       токены темы и стили
public/         фавикон, превью ссылки, видео, нарезанные картинки
images/         исходники картинок и точки фокуса
rag/            индексация, запись ответов, живой сервер (Python)
scripts/        сборка, dev-сервер, картинки, видео, превью
tests/          модульные тесты (node:test)
e2e/            сквозная проверка (Playwright)
```
